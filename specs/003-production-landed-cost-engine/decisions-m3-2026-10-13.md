## Decisions

- **D-M3-1 — One new table `production_records`, per country per ISO week.** Units produced against a target, with `expected_next_at` (the date the next batch is expected). Keyed by country and `period_week` (`YYYY-Www`, zero-padded on write), `product_id` nullable (the business records production at the country level, not always per bracelet type). The Produccion tile reads the latest recorded week (company-wide rollup across countries on the home); these records are what M4 reads to build the indirect-allocation denominator once OQ1 (the allocation window) is decided. This is the eleventh costing-area table; it is a SEPARATE forward migration (run_04) rather than an edit to run_03, because run_03 already shipped with M2 and an applied migration is never edited.

- **D-M3-2 — The arrival-cadence signal is computed from stored data, no send.** T-011's "arrival-cadence-overdue attention item" reads `expected_next_at <= today` on the latest per-country record. A blank or unparseable date is never overdue (no false alarm from bad data). This is the production-side analog of AC13's overdue-check-in discipline: the signal is derived, never a message. The whole send path stays in M7 behind its named-human gate.

- **D-M3-3 — The tile shows units vs meta honestly; no meta renders as "sin meta", never a zero target.** `units_target` NULL means no meta was set for that week; the tile shows the units and "sin meta esta semana" rather than inventing a 0% or 100%. With a meta, the caption is "meta N u · P%" and the tone is good at or above target, warn below. Same honesty discipline as the M2 costing completeness state.

- **D-M3-4 — The six BOM input categories are a named constant, not enforced membership.** `costing_service.INPUT_CATEGORIES` lists café, tostado, madera, hilo, piedras, broches (coffee, roasting, wood, thread, stones, clasps). `cost_inputs.category` stays a free string column (unchanged from M2); the constant is the canonical set the UI and the seed offer, and the materials component sums every BOM line regardless of category, so adding an input in any category shows up in the total (T-012). Not a CHECK constraint: the CEO may have a seventh input and the honest model does not block it.

- **D-M3-5 — Real write paths for the cost domain, not hand-seeded INSERTs.** T-012 and T-013 ship `record_cost_input` (RETURNING id, the products-create pattern), `record_bom_line`, `record_packaging_cost`, and `record_labor_batch` on `CostingRepository`. The breadth and labor tests exercise these write paths, so the enter-path is what is proven, not a raw INSERT the UI would never run.

- **D-M3-6 — Completed-basis labor extracted to a pure `labor_per_unit`.** M2 computed per-unit labor inline in `build_components` (batch payment / units completed). M3 extracts it to a pure `costing_service.labor_per_unit(batch_payment_cents, units_completed)` so the completed-basis rule (AC11 / T-013: a short batch raises the per-unit cost) is unit-testable and reused; `build_components` now calls it. Behavior is identical (the M2 landed-cost tests stay green); the change is testability, not arithmetic.

- **D-M3-7 — Produccion drill-down is a dedicated page `/produccion/{phone}`, owner-gated, reusing the Costos page shape.** Second dedicated module page after Costos (D-M2-7). Same `require_tenant_match` owner gate, same `href_for`-absolute-route convention, same frozen design-system tokens (indigo #4F46E5, Inter + JetBrains Mono, the two-layer shadow, recolored dark mode, shape-based severity cue). The two-rooms supplier split is still M6.

- **D-M3-8 — `production_records` lands in all four schema sources.** New Postgres tenants get it from `create_tenant_schema` (database_pg.py); new SQLite tenants from `tenant_manager._get_default_schema`; the SQLite reference schema (`root_archive/init_complete_database.sql`) carries it (with its DROP before products, since it REFERENCES products) so the test suite seeds it; existing Postgres tenants get it from the forward loop `postgres/migrations/run_04_production_table.py` over `public.tenants`, idempotent (CREATE TABLE IF NOT EXISTS) with per-schema try/rollback/continue so one bad schema does not abort the loop (the same discipline as run_03).

- **D-M3-9 — The monthly indirect denominator is deferred to M4, not shipped in M3 (amended post-council).** An earlier draft of this run shipped `ProductionRepository.units_produced_in_month`. The council (Marcus, Winston) flagged two problems: a raw SUM double-counted same-week append-only corrections, and attributing a week to a month by `recorded_at` (the data-entry date) is wrong — AC12 says "units produced that month." Both are symptoms of building the denominator before OQ1 (calendar month vs rolling trailing window, owned by Dario + the CEO) is decided. The method was removed; M3 ships the production records, and M4 builds the denominator against them once OQ1 lands. **M4 guidance:** attribute units by the production period (derive the month from `period_week`, or add an explicit produced-on date), never by `recorded_at`, and sum the newest row per (country, period_week) so a correction is not double-counted.

## Post-council amendment

A six-lens council (Winston architecture, Marcus cost-model, Amelia dev-reality, Tamir security, Edut honesty, Kaze client-surface) reviewed the change-set adversarially in parallel. First pass: Tamir/Edut/Kaze APPROVE-WITH-NITS, Winston/Amelia/Marcus BLOCK. The load-bearing blocker was found independently by three lenses: `latest_per_country` returned a duplicate row for a same-week append-only correction (no newest-id tiebreak per country), making the drill-down double-show a country and the overdue scan double-count. Fixes applied inline and re-reviewed (all three BLOCKs cleared to APPROVE-WITH-NITS):
- `latest_per_country` and `week_rollup` pick the newest row per country via a correlated subquery (`p.id = (SELECT x.id ... ORDER BY period_week DESC, id DESC LIMIT 1)`), portable on SQLite and Postgres.
- The home tile is a deterministic company-wide rollup of the latest week (units and targets summed across countries), replacing a single country's last-inserted row (Winston MED).
- `period_week` is zero-padded on write via `normalize_week` so lexical ordering is sound (Amelia/Marcus MED); malformed input raises.
- `units_produced_in_month` removed, deferred to M4 (Marcus HIGH/MED; see amended D-M3-9).
- `pct_of_target` floors to 1% for tiny-but-nonzero progress (Edut LOW); template overdue-date guard + behind-target bar warn tone (Kaze LOW).
Accepted without change (documented): negative `units_completed` already rejected by `CHECK (>= 0)` in all four schema sources (Marcus LOW); banker's rounding (Marcus NIT, consistent/harmless); CORS `allow_origins=*` pre-existing, tracked for M6 (Tamir LOW); a BOM missing an entire category reads complete because there is no ground-truth required-set — `INPUT_CATEGORIES` is a label registry, not enforced membership (Edut LOW, inherent model limitation).
